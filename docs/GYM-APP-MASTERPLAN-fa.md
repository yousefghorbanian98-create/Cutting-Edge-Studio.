## ۰. خلاصه مدیریتی (۶۰ ثانیه‌ای)

- ایده شما یک «سوپر-اَپ باشگاه» است: عضویت + آفر + برنامه + آموزش + ورود با چهره + موتور برنامه‌ریزی شخصی مبتنی بر AI.
- **قوی‌ترین بخش ایده شما** (و تمایز واقعی‌تان در بازار) همان ۱۴ دامنه «سلامت-عملکردی» است: هیچ‌کس برنامه را حول «تحرک، تعادل، مکانیک بلند کردن بار، کنترل تنفس، مدیریت بار…» نمی‌سازد. همه بدنسازی کلیشه‌ای می‌فروشند.
- **بزرگ‌ترین حلقه‌های گمشده ایده**: پنل مربی/مدیر، سیستم پرداخت و اشتراک، رزرو کلاس، چرخه «ارزیابی → برنامه → اجرای ثبت‌شده → بازآزمایی»، لایه حقوقی داده بیومتریک، و موتور قواعد علمی (AI نباید بی‌نظارت بنویسد).
- **توصیه طلایی**: با فیس‌آیدی شروع نکنید. MVP را با QR شروع کنید، فیس‌آیدی را در فاز سوم بیاورید. ورود با چهره هم‌زمان سخت‌افزار، قانون حریم خصوصی و انتظارات را بالا می‌برد.
- AI را «ترکیبی» طراحی کنید: موتور قواعد علوم ورزشی (تصمیم‌گیرنده) + زبان‌پرداز برای توضیح و انگیزش + **تأیید انسانی مربی** قبل از تحویل برنامه.

### B. لایه علمی و برنامه‌ریزی (تمایز اصلی شما)

| المان | چرا لازم است |
|---|---|
| **تعریف عملیاتی «غیرکلیشه‌ای»** | «شخصی‌سازی» یعنی: ورودی‌های فرد ← موتور قواعد ← دوره‌بندی ← بازبینی مربی. اگر این زنجیره تعریف نشود، خروجی همان برنامه آماده با نام مشتری است |
| **کتابخانه حرکات با ویدیو + معادل‌ها** | هر حرکت باید «جایگزین» داشته باشد (زانودرد، دستگاه اشغال، نبود دستگاه). فهرست دستگاه‌های **باشگاه خودتان** باید در سیستم باشد |
| **دوره‌بندی (Periodization)** | میکروسیکل/مزوسیکل، پیش‌بارگذاری تدریجی (progressive overload)، هفته دی‌لود — بدون این «علمی» نیست |
| **چرخه ارزیابی مجدد** | هر ۶–۸ هفته بازآزمایی ۱۴ دامنه + اندازه‌گیری ← برنامه نسل بعد |
| **جایگزین‌های پیکرسنجی** | جکسون-پولاک به اندازه‌گیر حرفه‌ای (کالیپر) نیاز دارد و دقت خوداندازی پایین است. گزینه‌ها: BIA (ترازوی آنالیز)، پروتکل ISAK (دورها)، عکس استانداردشده، یا ترکیب |
| **ماژول تغذیه** | پایگاه داده غذایی (ایرانی یا اروپایی بسته به محل باشگاه)، حساسیت‌ها، ترجیحات، بودجه، مکمل‌ها، اهداف کالری/پروتئین |
| **یکپارچگی پوشیدنی‌ها** | Apple Health / Google Fit / ساعت: خواب، ضربان قلب، HRV، قدم‌ها ← ورودی موتور ریکاوری |
| **حلقه بازبینی مربی (Human-in-the-loop)** | AI پیشنهاد می‌دهد ← مربی تأیید/ویرایش می‌کند ← تحویل. هم کیفیت بالا می‌رود، هم مسئولیت حقوقی مدیریت می‌شود |
| **پروتکل ریکاوری و مدیریت بار** | ثبت خواب، استرس، درد عضلانی، RPE جلسه (session-RPE × مدت)، هشدار اورترینینگ |

## ۳. پارامترهای ورودی موتور شخصی‌سازی (مدل داده)

این فهرست «پرسشنامه ورودی» سیستم شماست. هرچه کامل‌تر، خروجی غیرکلیشه‌ای‌تر:

**الف) مشخصات فردی:** سن، جنس، قد، وزن، سابقه تمرینی (سن تمرینی)، شغل (نشسته/فعال)، سطح مهارت.

**ب) هدف (چندگانه با وزن اولویت):** کاهش چربی، افزایش عضله، سلامت عمومی، اصلاح وضعیت بدنی، آمادگی برای زندگی روزمره، آمادگی مسابقه‌ای (درصد کمی از اعضا)، بازگشت پس از آسیب.

**ج) محدودیت‌ها:** آسیب فعلی/سابقه جراحی، درد (نواحی)، فشارخون، دیابت، بارداری، داروها، محدودیت مفصلی، ترس از حرکت (fear of movement).

**د) منابع زمانی:** جلسات در هفته، مدت هر جلسه، ساعت ترجیحی، روزهای ممکن، امکان تمرین خانگی.

**ه) تجهیزات:** دستگاه‌های موجود در باشگاه شما (فهرست دقیق)، تجهیزات خانگی (کش، دمبل، هالتر).

**و) ترجیحات:** حرکات محبوب/نامحبوب، تک‌نفره/گروهی، موسیقی، سابقه بدنسازی سنتی یا کراس‌فیت یا…

**ز) داده‌های بدنی:** وزن، چین‌خوردگی‌ها (جکسون-پولاک ۳ یا ۷ نقطه‌ای)، دور کمر/باسن/بازو، درصد چربی، عکس استانداردشده (جلو/بغل/پشت)، فشارخون استراحت، ضربان قلب استراحت.

**ح) نمرات پایه ۱۴ دامنه** (بخش ۵ همین سند).

**ط) وضعیت ریکاوری:** ساعت و کیفیت خواب (پرسشنامه ساده یا PSQI)، سطح استرس، میانگین قدم روزانه، HRV (در صورت وجود ساعت).

**ی) رفتار و انگیزش:** سابقه پایبندی به برنامه‌های قبلی (درصد جلسات انجام‌شده)، دلیل ترک برنامه‌های قبلی، سطح انگیزش (مقیاس ۱ تا ۱۰)، ترجیح پشتیبانی (پیام/حضوری/هر دو).

**ک) محیط:** ساعات کاری، استرس شغلی، امکان پخت‌وپز، سفرهای مکرر.

**خروجی‌های موتور:** طرح هفتگی (حرکت + ست + تکرار + RPE + استراحت)، برنامه تغذیه (کالری، پروتئین، چیدمان وعده‌ها)، پروتکل ریکاوری (خواب، کشش، تنفس)، نقاط بازآزمایی، «پلن B» برای روزهای ازدست‌رفته، و توضیح فارسی «چرا این برنامه برای توست» (اینجا LLM به کار می‌آید).

## ۴. موتور برنامه‌ریزی: چطور «علمی و غیرکلیشه‌ای» واقعی شود

سه لایه ترکیبی — نه فقط هوش مصنوعی متن‌ساز:

1. **موتور قواعد (Rule Engine / الگوریتم):** تصمیم‌گیرنده اصلی. بر اساس استانداردهای ACSM/NSCA: تعیین سطح ← انتخاب قالب تمرینی (مثلاً تمام‌بدن برای مبتدی، تفکیک بالا/پایین برای متوسط) ← محاسبه حجم هفتگی هدف ← پیش‌بارگذاری تدریجی ← دی‌لود هر ۴–۶ هفته. قواعد سقف (guardrails): سقف افزایش حجم هفتگی، ممنوعیت حرکات مرتبط با آسیب، سقف RPE برای مبتدی.
2. **زبان‌پرداز (LLM):** فقط برای توضیح فارسی برنامه، پاسخ به سؤال، انگیزش، و بازنویسی. هرگز تصمیم بار تمرینی را مستقیم به LLM نسپارید.
3. **تأیید انسانی (مربی):** در فاز اول، مربی هر برنامه را قبل از تحویل تأیید می‌کند. به‌تدریج برنامه‌های پرخطر (آسیب، بارداری، فشارخون) همیشه دستی بمانند.

زنجیره اجرا: `جمع‌آوری ورودی → نرمال‌سازی → تعیین سطح → انتخاب قالب → دوره‌بندی ۸ هفته‌ای → تحویل ← تأیید مربی → ثبت اجرا → بازآزمایی → نسل بعدی برنامه`

نکته مهم: **«غیرکلیشه‌ای» بودن یعنی همین زنجیره بازخورد**؛ نه صرفاً متن متفاوت.

| ۸ | هماهنگی و مهارت حرکتی | تست T، پرش جهت‌دار، واکنش | ثانیه / سانتی‌متر | ۸ هفته |
| ۹ | مکانیک بدن و بلند کردن بار | چک‌لیست فرم ددلیفت/اسکات با وزن سبک | امتیاز ۰–۱۰ | ۸ هفته |
| ۱۰ | قدرت گرفتن و مهارت دست | دینامومتر دست، آویزان شدن (dead hang) | کیلوگرم / ثانیه | ۸ هفته |
| ۱۱ | تنفس و کنترل فشار | تست کنترل تنفس (تنفس دیافراگمی)، ضربان تنفس استراحت | امتیاز / تنفس در دقیقه | ۶ هفته |
| ۱۲ | بازیابی، خواب، مدیریت بار | پرسشنامه خواب کوتاه، session-RPE × مدت، HRV | امتیاز / AU | مستمر |
| ۱۳ | پیشگیری از آسیب و آگاهی بدن | FMS (حرکات انتخابی)، مقیاس درد (0–10) | امتیاز | ۸ هفته |
| ۱۴ | مهارت‌های پایه زندگی ورزشی | چک‌لیست: گرم‌کردن، آبرسانی، نرخ پایبندی، دانش پایه | امتیاز | ۸ هفته |

خروجی بصری: **نمودار راداری ۱۴ محوره** هر عضو + نمره کل «آمادگی سلامت-عملکردی» (۰–۱۰۰). این نمودار، هم ابزار فروش است، هم انگیزه عضو برای بازگشت.

## ۶. معماری فنی پیشنهادی

```
[ اپ موبایل — Flutter ]   [ کیوسک تبلت — PWA ]   [ پنل وب مربی/مدیر — React ]
            \                      |                        /
             \                     |                       /
              ———————— [ API — FastAPI + PostgreSQL ] ————————
                                   |
        ————————————————————————————————————————————————
        |              |               |               |
   [ موتور قواعد ]  [ LLM توضیح ]  [ سرویس چهره ]  [ سرویس پرداخت/اعلان ]
        |                                 |
   (قواعد ACSM/NSCA)              [ گیت ورود: دوربین + لبه + رله ]
```

- **چهره‌شناسی:** پردازش روی دستگاه لبه (on-device) بهتر از ابری است: سریع‌تر، امن‌تر، آفلاین. الزامات: تشخیص زنده‌بودن (liveness ضد عکس/ویدیو)، ذخیره قالب رمزنگاری‌شده، سرعت < ۲ ثانیه، نور محیطی مناسب و زاویه دوربین.
- **سخت‌افزار گیت:** دوربین USB/شبکه + Raspberry Pi یا مینی‌پی‌سی + رله کنترل تورن‌استایل/درب + نمایشگر کوچک تأیید + پشتیبان QR.
- **کیوسک:** همان وب‌اپ در حالت کiosk، با timeout نشست (حفظ حریم خصوصی نفر قبلی!) و حالت ضدعفونی‌شدن صفحه لمسی.

## ۷. فازبندی نقشه راه (توصیه اجرایی)

### فاز ۰ — کشف و طراحی (هفته ۱ تا ۴)
- مصاحبه با ۱۰–۱۵ عضو فعلی: چه چیزی واقعاً می‌خرند؟
- تعریف MVP روی «یک صفحه»
- طراحی جریان‌های کاربر (user flow) و مدل داده
- تصمیم‌های کلیدی: کشور محل باشگاه (قانون/درگاه)، بودجه، تیم

### فاز ۱ — MVP (ماه ۲ تا ۴) ← «بدون فیس‌آیدی»
- ثبت‌نام/عضویت + پروفایل + PAR-Q+
- آفرها + اعلان‌ها
- تحویل برنامه تمرینی (دستی توسط مربی از پنل) + محتوای آموزشی
- چک‌این QR + حضور و غیاب
- پنل مربی/مدیر + پرداخت/اشتراک
- **خروجی فاز: باشگاه شما روزانه روی اپ کار می‌کند**

### فاز ۲ — موتور هوشمند (ماه ۵ تا ۷)
- ارزیابی ۱۴ دامنه + نمودار راداری + اندازه‌گیری‌ها
- موتور قواعد + پیشنهاد برنامه + تأیید مربی + تغذیه
- پیگیری پیشرفت و چرخه بازآزمایی
- کیوسک داخل باشگاه (نسخه اول: پرسشنامه + نمایش برنامه)

### فاز ۳ — ورود با چهره و رشد (ماه ۸ تا ۱۰)
- ثبت چهره + گیت ورود + liveness + رضایت‌نامه حقوقی
- گیمیفیکیشن، چالش‌ها، جامعه
- پوشیدنی‌ها، ریکاوری و مدیریت بار
- گزارش‌های کسب‌وکار و پیش‌بینی ریزش

### فاز ۴ — مقیاس (ماه ۱۱+)
- چندشعبه‌ای، فروش اشتراک AI به باشگاه‌های دیگر (B2B)، مربی آنلاین

## ۱۰. گام‌های عملی ۳۰ روز آینده

- [ ] **هفته ۱:** مصاحبه با ۱۰ عضو (چه چیزی می‌خرند؟ چرا می‌مانند/می‌روند؟) + تعیین بودجه واقعی
- [ ] **هفته ۲:** نوشتن «MVP روی یک صفحه» + طراحی ۵ جریان اصلی (ثبت‌نام، دریافت برنامه، چک‌این، آفر، پروفایل)
- [ ] **هفته ۳:** نهایی‌کردن پرسشنامه ورودی (بخش ۳) + پروتکل ۱۴ دامنه (بخش ۵) با یک مربی بدنسازی
- [ ] **هفته ۴:** انتخاب مسیر تیم/فناوری (الف/ب/ج) + شروع طراحی مدل داده و UI

### تصمیم‌های کلیدی که باید همین امروز بگیرید:
1. باشگاه در کدام کشور است؟ (قانون داده، درگاه پرداخت، مارکت توزیع)
2. آیا تیم فنی دارید یا برونسپاری؟
3. فیس‌آیدی در کدام فاز؟ (پیشنهاد: فاز ۳)
4. چه کسی محتوای علمی برنامه‌ها را تضمین می‌کند؟ (یک مربی تحصیل‌کرده به‌عنوان «مسئول علمی»)
5. پایلوت با چند عضو شروع می‌کنید؟ (پیشنهاد: ۲۰–۵۰)

## جمع‌بندی

ایده شما به‌خودی‌خود قوی است؛ چیزی که کم دارد «اسکلت اجرایی» است: پنل مربی، پرداخت، چرخه ارزیابی-بازآزمایی، موتور قواعد علمی، لایه حقوقی بیومتریک، و فازبندی محافظه‌کارانه. با «۱۴ دامنه آمادگی سلامت-عملکردی» به‌عنوان ستون تمایز و MVP باریکِ بدون فیس‌آیدی شروع کنید؛ در ۶ ماه اول چیزی خواهید داشت که رقبا ندارند.
